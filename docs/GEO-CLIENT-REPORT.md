**분석 일자:** 2026년 6월 8일
**분석 방식:** 소스 기반 분석 (코드베이스, `index.html`, 렌더링 아키텍처)

> **분석 범위 안내:** 본 분석은 실제 배포된 사이트가 아니라 애플리케이션 소스 코드를 대상으로 수행되었습니다. 실서비스에서만 확인 가능한 항목 — HTTP 보안 헤더, 실제 크롤러 응답, CDN 설정, 외부 브랜드 노출 — 은 *미확인*으로 표시했으며, 운영 URL이 확보되면 재확인이 필요합니다. 확인할 수 없는 항목은 추정 대신 그 사실을 그대로 명시했습니다.

## 핵심 요약 (Executive Summary)

본 분석은 퍼스널 컬러 셀프 테스트 — 컬러 퀴즈, 12타입 컬러 백과사전, 공유 가능한 결과 페이지를 갖춘 한국어/영어 이중 언어 React 단일 페이지 앱 — 을 AI 검색 준비도의 5개 축으로 평가했습니다. 사이트의 종합 **GEO 준비도 점수는 32/100점으로, "주의 필요(Needs Attention)" 등급**에 해당합니다. 가장 영향이 큰 발견은 아키텍처에 있습니다. 사이트가 전적으로 브라우저에서 렌더링(클라이언트 사이드 렌더링)되기 때문에, JavaScript를 실행하지 않는 AI 크롤러는 사실상 빈 페이지를 받게 됩니다 — 풍부한 컬러 타입 콘텐츠, 퀴즈, 백과사전이 대부분의 AI 검색 플랫폼에 보이지 않습니다. 우선순위가 가장 높은 3가지 개선 과제는 다음과 같습니다: (1) 사전 렌더링(pre-rendering) 또는 서버 사이드 렌더링으로 초기 HTML에 페이지 콘텐츠가 담기도록 하기, (2) Schema.org 구조화 데이터와 페이지별 메타 태그 추가, (3) 현재 누락된 기초 탐색 파일 — `robots.txt`, `sitemap.xml`, `llms.txt` — 게시. 분석 시점에 애널리틱스·트래픽 데이터가 제공되지 않았고 사이트가 상업용이 아닌 무료 소비자 도구로 보이므로, 본 리포트는 영향도를 금액이 아닌 인용 가능성(citation probability)과 GEO 점수 단위로 표현했습니다. 매출 추정에는 본 분석이 접근할 수 없었던 트래픽 데이터가 필요합니다.

## 인용 가능성 분석 (Citability Analysis)

사이트에는 6개의 논리적 페이지가 있습니다: 홈(`/`), 소개(`/about`), 타입 백과사전(`/types`), 개별 타입 페이지(`/types/:typeId`), 테스트(`/test`), 결과(`/results`). 이 모두가 단일 title·description을 공유하는 동일한 JavaScript 렌더링 껍데기에서 제공되기 때문에, *개별* 페이지의 인용 가능성이 현재 제한되어 있습니다 — AI 시스템이 메타데이터만으로는 한 타입 페이지를 다른 페이지와 구분할 수 없습니다.

### 인용 가능성이 높은 페이지 (렌더링 개선 시 잠재력)

1. **`/types/:typeId` — 개별 컬러 타입 페이지.** 가장 강력한 인용 후보입니다: 단일 주제에 집중되어 있고, 다수의 제목(heading)을 갖췄으며, 명시된 컨설턴트 이론에 근거합니다. *개선:* 각 페이지에 고유한 title·description과 `Article`/`DefinedTerm` 스키마를 부여해 플랫폼이 특정 타입을 인용할 수 있게 하기.
2. **`/types` — 타입 백과사전 인덱스.** 자연스러운 "목록/개요" 답변 대상입니다. *개선:* 페이지별 title과 12개 타입을 나열하는 `ItemList` 스키마 추가.
3. **`/about` — 소개 페이지.** 제목 수(9개) 기준 가장 풍부한 단일 페이지로, 방법론과 출처를 담기에 적합합니다. *개선:* 컨설턴트 이론 인용을 눈에 띄게 노출하고 작성자/자격 정보 추가.

### 인용 가능성이 낮은 페이지

1. **`/test` — 퀴즈.** 인터랙티브하며 정적 콘텐츠와 제목이 없습니다. 본질적으로 인용 가능성이 낮고, 그래도 괜찮습니다 — 답변이 아니라 도구이기 때문입니다. *권장:* 현 상태 유지하되 크롤러가 진입하는 첫 페이지가 되지 않도록 하기.
2. **`/results` — 결과.** 콘텐츠가 런타임에 URL 쿼리 상태로부터 생성되어 크롤러가 읽을 것이 없습니다. *권장:* sitemap에서 제외 — 사용자별 개인 산출물입니다.
3. **현재의 모든 콘텐츠 페이지.** 초기 HTML에 콘텐츠가 담기기 전까지는 강력한 타입 페이지조차 사실상 인용될 수 없습니다. *권장:* 아래의 렌더링 개선 과제 — 가장 높은 ROI의 콘텐츠 투자입니다.

**비즈니스 영향:** 개별 컬러 타입 페이지가 귀사의 최고의 AI 인용 자산입니다. 이 페이지들을 사전 렌더링하고 각각에 고유한 메타데이터와 스키마를 부여하는 조합이 AI 노출을 위한 단일 최고 수익 콘텐츠 투자입니다.

### 현재 구현 상태

| ItemList / DefinedTerm (타입 페이지) | 없음 | 누락 | 높음 — 플랫폼이 특정 컬러 타입을 인용하도록 지원 |

사이트는 현재 **어떤 종류의 구조화 데이터도 출력하지 않습니다.** 이는 백지 상태의 기회입니다: 고칠 깨진 스키마가 없고, 추가할 스키마만 있습니다. Open Graph와 Twitter Card 태그는 `index.html`에 *존재*하며 이는 견고한 소셜 공유 기반입니다 — 그러나 Open Graph는 Schema.org를 대체하지 못하며, `og:image`가 상대 경로(`/og.png`)를 사용하고 있어 공유 시 안정적으로 표시되려면 절대 URL로 바꿔야 합니다.

운영 도메인이 정해지면 Organization, WebSite, 컬러 타입 페이지용 JSON-LD를 최소한의 개발 공수로 준비할 수 있습니다.

## llms.txt — AI 콘텐츠 가이드

| 파일 | 상태 | 권장 조치 |
|---|---|---|
| `/llms.txt` | 누락 | 생성 — 도구 설명 및 백과사전 페이지 링크 |
| `/llms-full.txt` | 누락 | 선택 — 전체 컬러 타입 설명 포함 |

**비즈니스 담당자를 위한 설명:** `llms.txt`는 (`robots.txt`와 유사하게) AI 시스템에 사이트가 무엇에 관한 것이고 어떤 페이지가 가장 중요한지 알려주는 신흥 표준입니다. 빠르게 추가할 수 있는 작은 정적 파일이며, 아직 이를 도입하지 않은 경쟁사보다 브랜드를 앞서게 합니다.

### 예상 효과

본 분석에서 식별된 구체적 공백을 기준으로:

- **즉시 개선만으로도**(탐색 파일 + 기본 스키마) GEO 점수를 약 **8~12점** 끌어올릴 수 있습니다. 현재 완전히 부재한 엔티티·탐색 신호를 마련하는 효과가 큽니다.
- **계획 전체를 구현**하면 — 사전 렌더링을 핵심 축으로 — 점수를 약 **75~80/100**까지 끌어올릴 수 있습니다. 렌더링 개선이 콘텐츠·스키마 작업의 가치를 동시에 해제하기 때문입니다.
- **금액 추정치는 의도적으로 생략**했습니다. 애널리틱스·트래픽 데이터가 제공되지 않았고 사이트가 무료 소비자 도구로 보입니다. 업계 벤치마크상 2026년 말까지 AI 검색이 자연 유입의 25~40%를 견인할 것으로 전망되므로 노출 상승 여지는 분명합니다 — 다만 이를 금액으로 환산하려면 본 분석이 접근할 수 없었던 트래픽·전환 데이터가 필요합니다. 후속 단계에서 근거 있는 추정이 가능하도록 애널리틱스 연동을 권장합니다.

## 부록 (Appendix)

### 방법론

본 GEO 분석은 **소스 기반 분석**으로 다음을 활용해 수행되었습니다:

- **검토한 코드베이스:** `index.html`, `public/` 디렉터리, `src/pages/` 하위 6개 라우트 페이지, `src/i18n/translations.ts`의 i18n 콘텐츠, 렌더링/빌드 설정(Vite + React 19, react-router-dom v7, Vercel SPA rewrites).
- **식별된 페이지:** `/`, `/about`, `/types`, `/types/:typeId`, `/test`, `/results`.
- **평가 플랫폼:** Google AI Overviews, ChatGPT, Perplexity AI, Google Gemini, Bing Copilot.
- **수행한 점검:** 렌더링 아키텍처, `robots.txt`/`sitemap.xml`/`llms.txt` 존재 여부, 구조화 데이터(JSON-LD) 존재 여부, 메타 태그 및 Open Graph 커버리지, 라우트별 메타데이터 처리, 콘텐츠 구조(제목 사용), E-E-A-T 출처 신호.
- **분석 일자:** 2026년 6월 8일.

**한계:** 실서비스에서만 확인 가능한 신호는 검증하지 못했습니다 — HTTP 보안 헤더, 실제 크롤러 응답, Core Web Vitals 실측 데이터, CDN/호스트 동작, 외부 브랜드 노출. 이들은 본문 전반에서 *미확인*으로 표시했으며 운영 배포 환경에서 재확인해야 합니다.
