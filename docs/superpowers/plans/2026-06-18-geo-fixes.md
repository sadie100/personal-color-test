# GEO Audit Fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the on-site GEO gaps from [GEO-AUDIT-REPORT.md](../../../GEO-AUDIT-REPORT.md) (composite 46/100), prioritizing high-severity, low-effort fixes first.

**Architecture:** All head/meta/schema is emitted at SSG build time by `prerender.js`, driven by the centralized route table in `src/seo/routeMeta.ts`. JSON-LD is generated by a new pure TS function (`src/seo/jsonLd.ts`) re-exported through `src/entry-server.tsx` so `prerender.js` can inject it. Config-only fixes (security headers, soft-404) go in a new `vercel.json`. Content fixes (footer, comparison table, FAQ, author bio) are React/i18n changes.

**Tech Stack:** React 19 + TypeScript, Vite SSG (custom `prerender.js`), react-router-dom v7, Tailwind v4, Vitest, Vercel hosting.

## Global Constraints

- **No credential claims.** The creator holds NO personal-color certification (see memory `creator-no-color-certification`). Author/footer/schema copy must say the site *references/learns from* the 한국분장예술인협회 2급 curriculum theory — never that the creator is certified. Build trust via transparency + disclaimer, not credentials. Omit `jobTitle` from `Person` schema; `knowsAbout` (interest areas) is fine.
- **Real links only.** `sameAs` and contact links must be real profiles/addresses — never fabricate.
- **Bilingual parity.** Every head/schema/content change must cover both `ko` (`/*`) and `en` (`/en/*`) routes. Korean schema on `/*`, English on `/en/*`, with matching `inLanguage`.
- **SSG-time only.** JSON-LD must be in the static HTML `<head>` (via `prerender.js`), never injected client-side — AI crawlers don't run JS.
- **Match existing style.** Follow the regex-replace + `headLinks()` pattern already in `prerender.js`; follow `routeMeta.ts` typing conventions.

- [ ] **Step 3: Implement `src/seo/jsonLd.ts`.** Pure function, data-driven from existing modules. (Use `translations[lang].types[slug].title` for names, `colorTypeMetas` for set membership, `route.title`/`route.description` for Article/App copy. `knowsAbout` lists interest areas, NO certification. `name`/`sameAs` use module-level constants the author fills in — see Tier 4 input.)

```typescript
import { translations } from "../i18n/translations";
import type { ColorTypeSlug } from "../types";
import { colorTypeSlugs } from "../utils/colorTypeSlug";
import { localizePath } from "../utils/localizePath";
import { ORIGIN, type PrerenderRoute } from "./routeMeta";

// Author identity — fill from user input (Tier 4). Handle is fine; never claim a credential.
const AUTHOR_NAME = "Personal Color Self Test"; // [REPLACE with name/handle once provided]
const AUTHOR_SAMEAS: string[] = []; // [REPLACE with real profile URLs, or leave empty]

const publisher = (lang: "ko" | "en") => ({
  "@type": "Person",
  "@id": `${ORIGIN}/#publisher`,
  name: AUTHOR_NAME,
  url: `${ORIGIN}${localizePath(lang, "/about")}`,
  knowsAbout:
    lang === "ko"
      ? ["퍼스널 컬러", "PCCS 톤 시스템", "사계절 컬러 이론", "색채 이론"]
      : ["Personal color analysis", "PCCS tone system", "Seasonal color theory", "Color theory"],
  ...(AUTHOR_SAMEAS.length ? { sameAs: AUTHOR_SAMEAS } : {}),
});

export function buildJsonLd(route: PrerenderRoute): object[] {
  const { lang, logical, url, title, description } = route;
  const t = translations[lang];
  const abs = (logicalPath: string) => `${ORIGIN}${localizePath(lang, logicalPath)}`;
  const pub = { "@id": `${ORIGIN}/#publisher` };

  if (logical === "/") {
    return [
      publisher(lang),
      {
        "@type": "WebSite",
        "@id": `${ORIGIN}/#website`,
        url: `${ORIGIN}${url}`,
        name: title,
        description,
        inLanguage: lang,
        publisher: pub,
      },
      {
        "@type": "WebApplication",
        "@id": `${ORIGIN}/#app`,
        name: title,
        url: `${ORIGIN}${url}`,
        applicationCategory: "LifestyleApplication",
        operatingSystem: "Web browser",
        isAccessibleForFree: true,
        offers: { "@type": "Offer", price: "0", priceCurrency: "USD" },
        description,
        inLanguage: lang,
        publisher: pub,
      },
    ].map((o) => ({ "@context": "https://schema.org", ...o }));
  }

  if (logical === "/about") {
    return [
      {
        "@context": "https://schema.org",
        "@type": "Article",
        "@id": `${abs("/about")}#article`,
        headline: title,
        description,
        url: abs("/about"),
        mainEntityOfPage: abs("/about"),
        inLanguage: lang,
        image: `${ORIGIN}/og.png`,
        author: pub,
        publisher: pub,
        speakable: { "@type": "SpeakableSpecification", cssSelector: ["h1", "h2"] },
      },
    ];
  }

  if (logical === "/types") {
    return [
      {
        "@context": "https://schema.org",
        "@type": "DefinedTermSet",
        "@id": `${abs("/types")}#set`,
        name: t.types.pageTitle,
        url: abs("/types"),
        inLanguage: lang,
        hasDefinedTerm: colorTypeSlugs.map((slug) => ({
          "@type": "DefinedTerm",
          "@id": `${abs(`/types/${slug}`)}#term`,
          name: t.types[slug].title,
          url: abs(`/types/${slug}`),
          inDefinedTermSet: `${abs("/types")}#set`,
        })),
      },
    ];
  }

  // /types/:slug
  const slug = logical.replace("/types/", "") as ColorTypeSlug;
  return [
    {
      "@context": "https://schema.org",
      "@type": "DefinedTerm",
      "@id": `${abs(logical)}#term`,
      name: t.types[slug].title,
      description: route.description,
      url: abs(logical),
      inDefinedTermSet: `${abs("/types")}#set`,
      inLanguage: lang,
    },
    {
      "@context": "https://schema.org",
      "@type": "BreadcrumbList",
      itemListElement: [
        { "@type": "ListItem", position: 1, name: lang === "ko" ? "홈" : "Home", item: abs("/") },
        { "@type": "ListItem", position: 2, name: t.types.pageTitle, item: abs("/types") },
        { "@type": "ListItem", position: 3, name: t.types[slug].title, item: abs(logical) },
      ],
    },
  ];
}
```

> Verify before shipping: `t.types[slug].title` and `t.types.pageTitle` exist for both langs (confirmed in `translations.ts` per exploration). If `localizePath` signature differs, adjust `abs()`.
